백엔드 기본기 로드맵

이론 중심 · 6개월~1년 · 각 챕터는 대표 교재의 목차를 따라 구성했어요

읽는 법

챕터마다 대표 교재(OSTEP, 1%의 네트워크 원리, Real MySQL 8.0, DDIA, 오브젝트 등)의 장 구성을 그대로 따라 내용을 정리했어요. 책을 함께 읽으면 가장 좋고, 책이 없어도 이 페이지만으로 각 장의 핵심 개념은 익힐 수 있어요.

각 장에는 개념 설명 → 백엔드 연결 → 핵심 정리 → 셀프 체크(답 보기) 순서로 들어 있어요. 셀프 체크에 스스로 답할 수 있으면 "이 장 학습 완료"를 체크하세요. 진행 상황은 이 브라우저에 저장돼요.

챕터 1~6이 기본기이고, 챕터 7부터는 그 위에 쌓는 확장 챕터예요. 확장 챕터는 기본기를 전제로 하니 챕터 1~6을 먼저 읽으세요. 확장 챕터끼리는 순서 없이 필요한 것부터 읽어도 돼요.

레벨은 두 가지예요. 주니어는 1~3년차가 반드시 알아야 하는 핵심 장만 보여줘요. 시니어는 전체 장에 더해, 각 장의 시니어 심화 박스(운영 중 장애 양상, 트레이드오프, 진단 방법)까지 보여줘요. 아래 "레벨" 버튼이나 각 챕터의 사이드바에서 바꿀 수 있고, 진행률은 선택한 레벨 기준으로 계산돼요.

시간이 부족할 때의 우선순위:

DB›OS (병행성·I/O)›네트워크›DDIA›나머지
전체 진행률 0%
CHAPTER 1 · 4~6주

운영체제

가상화(CPU·메모리), 병행성, 영속성. 스레드풀·커넥션 풀·이벤트 루프·GC가 동작하는 바닥.

기준 교재: OSTEP (Operating Systems: Three Easy Pieces)
CHAPTER 2 · 3~4주

네트워크

브라우저에서 서버까지 패킷이 흘러가는 전 과정. TCP·IP·DNS·LB·HTTP.

기준 교재: 성공과 실패를 결정하는 1%의 네트워크 원리 + HTTP 완벽 가이드
CHAPTER 3 · 6~8주 · 가장 중요

데이터베이스

InnoDB 아키텍처, 트랜잭션과 잠금, 인덱스, 옵티마이저, 실행 계획, 복제.

기준 교재: Real MySQL 8.0 (1·2권)
CHAPTER 4 · 상시 병행

자료구조와 알고리즘

복잡도, 해시, 트리, 그래프, 정렬·탐색, 그리고 실무에서 쓰는 자료구조.

기준 교재: Hello Coding 알고리즘 + Introduction to Algorithms(참고)
CHAPTER 5 · 8주 이상

분산 시스템과 설계

복제, 파티셔닝, 트랜잭션, 합의, 스트림 처리. 그리고 실무 설계 패턴.

기준 교재: 데이터 중심 애플리케이션 설계 (DDIA) + 대규모 시스템 설계 기초
CHAPTER 6 · 상시 병행

소프트웨어 설계

책임·역할·협력, 의존성 관리, SOLID, 클린 아키텍처, 테스트.

기준 교재: 오브젝트 + 클린 아키텍처
확장 1 — 실무에서 바로 필요한 것

기준 자료: OWASP Top 10 · ASVS

클래스 로딩, JIT, 메모리와 GC, 자바 메모리 모델, 동시성 도구, 진단.

기준 교재: 자바 병렬 프로그래밍 + 자바 최적화

USE·RED 방법론, 지연 분포, 프로파일링, 부하 테스트, 큐잉 이론과 용량 계획.

기준 교재: 시스템 성능 분석 (Systems Performance)
확장 2 — 매일 쓰는 기술의 내부
CHAPTER 10 · 2~3주

Redis

단일 스레드 모델, 자료형, 만료와 메모리, 영속화, 복제와 클러스터, 분산 락.

로그와 파티션, 프로듀서와 컨슈머 그룹, 복제와 내구성, 전달 보장, 운영.

기준 교재: 쿠버네티스 인 액션

학습 방법

  1. 순서대로 읽기 — 각 챕터는 교재 순서라서 앞 장이 뒤 장의 전제예요. 건너뛰지 말고 읽으세요.
  2. 실무와 연결하기 — 장마다 "백엔드에서는" 박스가 있어요. 우리 서비스에서 같은 것을 찾아보세요.
  3. 직접 재현하기 — 데드락, 실행 계획, 패킷을 직접 만들어 보고 관찰하세요. 읽기만 하면 남지 않아요.
  4. 답 보기 전에 먼저 말해보기 — 셀프 체크에 소리 내어 답하거나 글로 쓴 뒤 답을 여세요.
  5. 깊이 우선 — 넓게 훑기보다 DB 챕터 하나를 끝까지 파는 편이 효과가 커요.
